# Upstream synchronization

The OpenShift sync Make targets delegate to `cmd/upstream-sync`:

```sh
make sync-upstream-check # fetch refs and print a pinned plan
make sync-upstream-pr    # integrate/publish and upsert the sync PR
```

In a developer clone where `origin` is a personal fork and `downstream` is
`openshift/openshift-mcp-server`, target the downstream remote explicitly:

```sh
make sync-upstream-check ORIGIN_REMOTE=downstream
make sync-upstream-pr ORIGIN_REMOTE=downstream
```

The tool reads upstream and downstream remote names, validates their GitHub
repository identities, and pins the two `main` SHAs. Other base branches are
rejected. It reports overlapping paths and uses `git merge-tree --write-tree`
to preview merges. `plan` does not alter
the working tree or publish branches. `publish` runs integration in a temporary
worktree so the caller's checked-out branch remains untouched.

The planner considers only merged `main` refs; it does not enumerate or block
on open downstream PRs. After a sync PR lands, owners of affected downstream PRs
rebase or update their branches against the new downstream `main` and resolve
any resulting conflicts.

## Conflict PR safety

If the downstream/upstream preview conflicts, only the explicit generated
allowlist below can be resolved automatically. For other conflicts, the tool
does not create a synthetic merge commit or choose a side. A new sync branch
points to the pinned upstream commit, allowing a draft PR to show the incoming
changes and GitHub's merge-conflict state. The PR body records both source SHAs
and the conflicting paths.

Only these conflicts are eligible for automatic regeneration:

- `README.md` and `docs/configuration.md`, when each conflict hunk lies wholly
  inside a registered generated marker region (validated projects/toolsets in
  README; available toolsets/resources in configuration docs).
- `vendor/**`, regenerated by `go mod vendor` after a clean module merge.
- `pkg/mcp/testdata/*.json`, regenerated by the snapshot target.

`go.mod`, source files, unlisted paths, and any README/doc conflict outside a
generated marker remain human conflicts. For an allowlisted conflict, the tool
selects a temporary side only inside its isolated worktree, runs the matching
generator, and publishes only after the final merge is conflict-free. If a
generator fails, it falls back to the unresolved draft-PR path.

On later runs, an existing sync branch is fast-forwarded when its current head
is an ancestor of the new upstream commit. If it contains resolution commits,
the tool tries a clean merge in an isolated worktree; it preserves the published
head if that merge conflicts.

Configure downstream branch protection to require the
`upstream-sync/mergeable` commit status. It is successful only when the PR head
contains the pinned upstream commit and a current downstream-to-head merge
preview is clean. The tool publishes a failing status for unresolved conflicts
or stale upstream heads. Draft status provides an additional review signal but
is not a substitute for the required status check. Keep the repository's normal
CI test checks required as well; this sync status proves mergeability and
upstream coverage, not semantic correctness.

Clean integrations retain the existing `go mod tidy`, `go mod vendor`, README
and configuration generation, and test snapshot updates. Generated changes are
committed only inside the temporary worktree before the lease-protected branch
push. The caller's working tree and index are not staged or committed.
